# WORK 페이지 구현 기준

- 상위 디자인 계약: 바탕화면 SORO_원본_디자인_개발키트/design-system/DESIGN.md.
- 구성 근거: 2026-09-27 사용자가 제공한 구성 이미지. 디자인 근거로 사용하지 않는다.
- 제목 제안: Featured Work.
- 서브텍스트 제안: 업종의 특성과 일하는 방식을 담아, 각 기업에 맞는 공간을 만듭니다.
- 필터: 전체, 바이오, 반도체, IT, 건설, 제조, 미디어, 금융, 서비스. 전체 포함 9개.
- 프로젝트 데이터: 사용자 이미지에서 읽은 3건 + 사용자가 요청한 샘플 3건. 샘플 표시와 isDummy 플래그를 유지한다. PC·태블릿은 한 줄 3개, 모바일은 2열.
- 사진, 프로젝트명, 업종, 평수 상시 노출.
- 기본 UI: .sub-container > .sub-wrap > .sub-title + .work-filter + .work-list 원본 계층.
- 원본 보존: CSS 3개 원문, Pretendard Variable, 제목·서브텍스트·메타 타이포, 필터 베이지/검정, 정사각형 이미지와 얇은 선, 원본 gap.
- 구성 확장: 최신 사용자 요청에 따라 데스크톱·태블릿은 3열, 768px 이하는 원본 2열. 프로젝트 페이지 전용 상단 패딩은 PC 140px·모바일 96px, 제목 블록 아래 여백은 48px·24px, 제목과 설명 사이는 24px·16px, 필터 아래 여백은 36px·28px로 표시해 제목·필터·사진 사이에 여유를 둔다.
- 기능 확장: 데이터 필터, 실제 건수, aria-pressed/라이브 결과 안내, 빈 상태·전체 복귀, 키보드 focus, reduced-motion.
- 9개 버튼을 작은 화면에 담기 위해 flex-wrap을 추가. 사용자 요청에 따라 필터 컨테이너 배경은 투명하게 유지한다.
- 상단 메뉴: 사용자가 제공한 로고를 사용하고, 회사소개 / 프로젝트 / 프로세스 / 상담신청 순서로 배치한다. 상담신청은 검정 버튼이다. 데스크톱 30px 좌우 여백, 17px 메뉴 글자, 40px 간격은 원본 헤더 규칙을 따른다. 모바일은 원본처럼 검정 전체 화면 메뉴와 토글을 사용한다.
- 회사소개는 about.html, 프로세스는 process.html, 상담신청은 index.html#contact로 연결한다. 프로젝트는 work.html에 유지한다.
- 노보네시스 프로젝트는 `project-detail.html`로 연결한다. 상세가 없는 다른 카드에는 빈 링크를 만들지 않는다.
- 관찰용 가이드 CSS 및 이전 확장 토큰을 로드하지 않는다.
- 새로운 제목·고객 콘텐츠를 사용하므로 원본 페이지 전체 픽셀 일치를 주장하지 않는다.

## 고객 타이포 언어 규칙 (2026-09-27 사용자 지정)
페이지 제목 타이틀은 영문, 서브텍스트는 한글로 작성한다. 프로젝트명과 업종 등 데이터는 실제 이름을 유지한다. 원본 CSS의 타이포 수치는 변경하지 않는다.

## 프로젝트 상세 정보 영역 (2026-10-21)
- 최신 사용자 지정: 정보는 프로젝트 제목 바로 아래·대표 이미지 위에 2열×2행의 라인형 표로 배치한다. 대표 이미지 아래 설명 영역은 참고 이미지처럼 왼쪽 Project Overview 제목·오른쪽 설명문으로 배치한다. 첫 행 업종·프로젝트 유형, 둘째 행 면적·위치 순서다. 기존 흰 배경과 1,136px 최대 콘텐츠 너비, 프로젝트 내용과 사진 15장을 유지한다.
- PC에서 각 항목은 항목명과 값을 좌우로 정렬한다. 항목명 열은 128px, 값과의 간격은 24px다. 정보 그리드 사이 간격은 0이며 각 칸에 24px 패딩을 둔다. 표 위·아래에는 1px 검정 선, 행 사이에는 1px 검정 20% 선을 사용한다. 가운데 세로선과 좌우 외곽선은 두지 않는다. 항목명은 19px·굵기 700, 값은 19px·굵기 400이다.
- 768px 이하에서도 2열×2행을 유지하며, 각 항목 안에서 항목명 아래에 값을 배치한다. 내부 간격은 8px, 그리드 간격은 0이며 각 칸의 패딩은 상하 20px·좌우 12px다.
- 정보 표와 대표 이미지 사이, 대표 이미지와 소개 사이는 각각 PC 48px·모바일 32px다. 소개는 전체 콘텐츠 너비 안에서 1:3 비율의 두 열과 32px 간격을 사용한다. 왼쪽 Project Overview는 20px·굵기 500, 오른쪽 설명문은 19px·굵기 400·행간 1.8이다. 두 열의 상단을 정렬한다. 모바일은 제목 위·설명문 아래 한 열로 배치하고 사이에 20px 간격을 둔다.
- Info와 Gallery 표기는 제거한다. 정보·갤러리는 접근 가능한 영역 이름을 제공하고, 소개는 Project Overview 제목과 aria-labelledby로 연결한다. 설명 아래 80px 여백 뒤 기존 갤러리로 연결한다.
- 검증: `BASE_URL=http://127.0.0.1:60528/project-detail.html node tests/project-detail.cjs`. 1440·1024·768·390·320px에서 2열×2행 배치·사진 로딩·목록 진입·가로 넘침 없음을 확인했다. 화면 확인: `evidence/project-detail-information-table-1440.png`, `evidence/project-detail-information-table-390.png`.

## 프로젝트 상세 하단 탐색 (2026-10-21)
- 갤러리 아래 PC 80px·모바일 48px 간격으로 왼쪽 이전 프로젝트·오른쪽 다음 프로젝트를 배치한다. PC 글자 34px·굵기 300·화살표 40px, 모바일 글자 12px·굵기 400·화살표 20px다.
- 가운데 목록 버튼은 제거한다. project-detail.js는 projects.js의 detailHref가 등록된 프로젝트만 최신 연도순으로 정렬하고 현재 data-project-id 앞뒤 상세페이지를 연결한다. 이동 대상이 없으면 링크 없이 aria-disabled 상태로 표시한다. 현재 등록된 상세페이지는 노보네시스 한 건이다.
- 모바일 하단 패딩은 최소 216px와 safe-area를 확보해 페이지 끝에서 문의 위젯과 탐색 버튼이 겹치지 않도록 한다.
- 검증: 기존 상세 회귀 테스트 통과. 1440·768·390·320px 넘침 없음, 테스트 데이터에서 이전·다음 링크 활성화, 이전·다음 두 버튼 배치를 확인했다. 화면: evidence/project-detail-navigation-1440.png, evidence/project-detail-navigation-390.png, evidence/project-detail-navigation-320.png.

- 하단 탐색 버튼명은 이전 프로젝트·다음 프로젝트로 한글 표기한다. 글자와 화살표는 hover·키보드 focus-visible 시 브랜드 오렌지(--primary)로 바뀐다. 이동 대상이 없는 비활성 링크도 hover 색상은 동일하다.
