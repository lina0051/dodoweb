## Brand
- 디자인코드. 큰 영문 타이포, 넓은 여백, 흑백과 베이지, 원본 주황색 포인트, 정사각형 프로젝트 이미지.

## Product goals
- 기업 공간 프로젝트와 일하는 방식을 소개하고 프로젝트 탐색·상담으로 이어지게 한다.

- 원본 콘텐츠가 아닌 디자인코드의 제안 카피와 교체 가능한 데이터로 구성한다.

## Information architecture
- 메인: `/`, `index.html`.
- 프로젝트: `work.html`. 기존 9개 업종 필터·6개 데이터 유지.
- 프로세스: `process.html`. 계약 전, 계약 후·착공 전, 착공 후의 3개 구간과 9개 단계.
- 상담신청: `contact.html`. 프로젝트·프로세스 페이지와 동일한 `.sub-container`, `.sub-wrap`, `.sub-title`, `.btit`, `.stit` 타이틀 시스템을 사용한다. 제목·소개 크기는 PC 제목 `clamp(40px, 5vw, 96px)`·소개 `clamp(18px, 1.528vw, 22px)`, 모바일 제목 40px·소개 16px로 두 페이지와 맞춘다. 타이틀 상단 패딩은 PC 140px·모바일 96px, 블록 아래 여백은 PC 48px·모바일 24px로 통일한다. 본문은 좌측 상담 안내·연락처와 우측 프로젝트 정보 폼의 2열 구성이며 모바일에서는 한 열로 전환한다. 본문 소제목 `상담신청 하기`는 기존 크기의 90%로 PC `clamp(30.6px, 2.25vw, 43.2px)`·모바일 `clamp(28.8px, 8.3079vw, 37.8px)`로 표시한다.
- 상담신청 입력 항목(2026-10-20 전달 표 기준): 회사명 → 담당자명 / 직함 → 담당자 연락처 → 담당자 이메일 → 입주예정일 → 부동산 잔금일 → 전용면적 → 현장주소 → 문의내용. 입주예정일과 부동산 잔금일은 별도 날짜 입력이며 잔금일 아래 `(착공 가능 시기 확인용)` 안내를 연결한다. 전용면적 단위는 평으로 안내하고 하단 버튼은 `상담신청`으로 표시한다. 전달 이미지 본문의 현장주소 삭제·8개 지시와 표의 9개 항목이 상충하여, 구체적인 최종 순서표에 따라 현장주소를 유지한다.
- 새 회사소개: `about-new.html`은 기존 `about.html` 전체를 복사하고 별도로 수정하는 회사소개 페이지다. 지표·차별점 4개의 기존 카피와 아이콘을 유지한다. 원스톱 서비스 8개는 사용자 제공 설명을 각 카드에 넣고 인터넷 회선 신청·개통 별도 안내를 함께 표시한다. 픽토그램은 기존 크기의 125%로 확대하고 카드 높이는 문구 분량에 따라 자동으로 늘어나며 같은 행끼리 높이를 맞춘다. PC는 Key Figures 제목 좌측·내용 우측, Difference 내용 좌측(2열×2행)·제목 우측, One-stop Service 제목 좌측·내용 우측(4열×2행)으로 배치한다. 제목과 내용은 각각 화면 너비의 50%인 큰 직사각형 패널로 나누고, 패널 사이와 섹션 사이를 여백 없이 맞붙인다. 제목 칸은 기존 베이지(#f1efec), 내용 칸은 #e5e0db이며 좌우 교차 배치로 바둑판처럼 연결한다. 제목은 최대 88px이고 패널 내부에 64–100px의 상하 여백을 둔다. 1024px 이하는 제목→내용 순서로 쌓고, 모바일은 차별점·서비스를 2열로 표시한다. 흰색·연한 베이지 배경과 기존 오렌지 아이콘을 사용한다. Key Figures는 제목 아래 “축적된 경험과 전문성을 바탕으로 / 일하는 공간의 완성도를 높입니다.”를 넣고, 오른쪽 지표 3개를 간격 16px의 베이지 카드로 가로 한 줄에 나란히 표시한다. 카드 안은 항목명→수치→설명 순서이며, 모바일에서는 한 열로 배치한다. 카드 상단 항목명 3개는 기존 오렌지(--primary)로 표시한다. 숫자는 검은색·굵기 300으로 표시하고 단위(년·+)와 면허보유는 카드 타이틀과 동일한 굵기 500으로 표시하며 설명은 카드마다 두 줄로 간결하게 표시한다. 기존 14년·250+ 카운트업 모션을 유지한다. 공통 푸터·문의 위젯은 유지한다. 새 페이지의 두 번째 프로젝트 갤러리는 스크롤 고정을 해제하고 사진 네 장을 복제해 64초 주기로 왼쪽으로 자연스럽게 반복 이동한다. 사진 크기와 높낮이는 유지하며, 모션 감소 환경에서는 자동 이동 없이 가로 탐색을 제공한다. 기존 소개 페이지를 보관하고 공통 메뉴에 별도 `회사소개` 항목을 추가해 새 페이지로 연결한다. 기존 회사소개 페이지는 보관하되 공통 메뉴에서는 해당 링크를 제거한다. 새 페이지에서는 메인처럼 헤더를 첫 섹션 위에 겹치고, 메뉴·로고 색상은 메인과 같은 검은색 공통 스타일을 사용한다. 헤더는 아임웹 적용을 고려해 모든 페이지에서 겹침(투명 배경·검은 메뉴)과 스크롤(반투명 흰 배경·검은 메뉴)의 두 상태만 사용하며 페이지별 색상 예외를 두지 않는다. 첫 섹션은 제공한 슈퍼크리에이티브 사진(`assets/about/super-creative.jpg`)을 흑백·6px 블러 처리한 배경, 어두운 오버레이, 좌측 `CO+DE` / `협업으로 완성하는 공간 디자인`과 참고 이미지의 소개 문구로 구성한다. Pretendard, 기존 `.btit` 굵기 300·자간, `--title-text-gap`, 본문 19px·굵기 500을 사용한다. 타이틀 위 주황색 막대는 제거하고 텍스트 묶음은 섹션 하단에서 100px 여백을 두고 배치한다. 페이지 전용 변경은 `about-new.css`에 한정하며 이후 수정도 사용자 안내를 따른다.
- 소개 대안: `about-alt.html`. 기존 `about.html`은 유지하고, 영문 지표 레이블·검증된 수치·프로젝트 이미지 스트립을 중심으로 한 두 번째 소개 시안을 제공한다.
- 새 회사소개(`about-new.html`)의 전체 콘텐츠 좌우 기준선은 메뉴에 맞춰 PC 30px·모바일(≤768px) 20px로 통일한다. 히어로 텍스트, 프로젝트 갤러리 표시 영역, Key Figures·Difference·One-stop Service의 바깥 패널 안쪽 여백, 공통 푸터에 동일한 `--about-page-gutter`를 사용한다. 배경 패널은 화면 끝까지 이어지고 중앙 분할선은 화면 50%를 유지한다.
- 공통 메뉴: 회사소개 → 프로젝트 → 프로세스 → 상담신청. 회사소개는 `about-new.html`, 상담신청은 `contact.html`, 로고는 메인으로 연결한다.
- 메인 프로젝트 6건. 사진 프로젝트를 먼저 배치하고 로고 프로젝트를 뒤에 배치한다.

## Design principles
- 원본 CSS 사본을 수정하지 않는다. 새 구성은 `home.css`에서 문맥을 한정한다.
- 프로젝트·프로세스·상담신청 페이지의 타이틀 아래 소개 문구(`.sub-title .stit`)는 공통으로 굵기 400을 사용한다.
- 타이틀 영문, 설명 한글. 원본 `.btit`, `.award-*`, `.work-item`, `.faq-*`, `.more-btn` 문맥을 우선 재사용한다.
- OBSERVED: 원본 타이포·색·프로젝트 카드·연도별 행. DERIVED: 차별화·파트너 조합. EXTENDED: 슬라이더·클릭 FAQ·메뉴 연결.
- 원본 메인 전체와 픽셀 일치한다고 주장하지 않는다. 사용자 지정 구성과 콘텐츠를 원본 시각 언어로 조합한다.

## Visual language
- 메인 섹션과 페이지 상단 제목 영역은 공통 `--title-text-gap`·`--title-content-gap`을 사용한다. 1920px에서 제목과 서브텍스트 사이 24px·콘텐츠까지 80px, 1440px에서 18px·60px, 모바일에서 24px·40px다. 프로젝트는 제목 영역 뒤 필터부터 콘텐츠로 간주하며 필터와 카드 사이는 기존 여백을 유지한다. 회사소개는 기존 좌우 그리드와 갤러리를 유지하고 제목·소개 사이와 소개 블록 아래 여백만 공통값으로 맞춘다.
- 메인 배너·각 섹션의 서브텍스트와 회사소개 상단 소제목·설명문, 프로젝트·프로세스·상담신청 상단 소개 문구는 PC·모바일 모두 고정 19px·굵기 500으로 통일한다.
- Pretendard Variable. 원본 common.css의 일반 `.btit` 크기·행간·자간 유지.
- 히어로 제목은 원본 `.main-visual .btit` 기반. 모바일 슬라이드 내 두 줄 표시에 필요한 행간 1.1은 명시적 구성 확장이다. 사진의 상단은 유지하고 하단 60%에만 어두운 그라데이션 스크림을 적용해 제목 대비를 확보한다.
- 섹션 여백: 원본 `clamp(50px,10.417vw,200px)`에서 모바일 최소 80px로 확장. 좌우는 원본 20–30px.
- 흰색, #0a0a0a, #f1efec, #ff6338. 푸터 #ff7632.
- 카드 그림자와 범용 둥근 패널을 추가하지 않는다.
- Difference 아이콘은 64px 건축 도면형 모노라인으로 통일한다. 진한 구조선을 기본으로 하고 #ff6338은 기준점·인증·초점과 같은 핵심 정보에만 제한한다.
- 아이콘에 그라데이션, 그림자, 배경 원형, 큰 채움면을 사용하지 않는다. 모션은 아이콘의 배치와 바깥 프레임을 고정하고 내부 설계선·궤도·인증·초점만 상시 반복한다. `prefers-reduced-motion` 환경에서는 정지한다.

## Components
- 프로젝트 상세 정보 영역은 2026-10-21 최신 사용자 지정에 따라 프로젝트 제목 → 메타데이터(2열×2행 라인형 표) → 대표 이미지 → 왼쪽 Project Overview 제목(20px)·오른쪽 설명문(19px) → 갤러리 순서로 배치한다. PC의 각 항목은 항목명·값을 좌우 정렬하고, 모바일은 항목명 아래에 값을 둔다. 소개 제목·설명은 PC 1:3 비율과 32px 간격, 모바일 한 열과 20px 간격으로 배치한다. 정보 표와 대표 이미지 사이·대표 이미지와 소개 사이는 각각 PC 48px·모바일 32px, 소개와 갤러리 사이는 80px다. 정보 표는 위·아래와 행 사이에만 1px 가로선을 두며, 가운데 세로선은 사용하지 않는다. Info·Gallery 표기는 제거하며 기존 흰 배경·콘텐츠·사진 배치는 유지한다. 세부 기준은 `WORK-DESIGN.md`를 따른다.
- 플로팅 문의: 전체 페이지 오른쪽 하단에 카카오톡 → 인스타그램 → 문자 순서로 아이콘을 세로로 고정한다. 인스타그램은 `https://www.instagram.com/designcode_official/`을 새 창으로 연다. 푸터 하단 정보는 위젯과 겹치지 않도록 오른쪽 전용 여백(PC 104px·모바일 80px 및 safe-area)을 확보하며 Back to Top 링크는 표시하지 않는다. 사용자 스크린샷과 `https://canivon.com/` 기준으로 카카오는 노란 원형, 문자는 검정 원형 배경에 흰색 솔리드 문자 말풍선 아이콘을 사용한다. 데스크톱 56px·간격 16px·오른쪽/하단 24px, 모바일 48px·간격 12px·오른쪽/하단 16px 및 safe-area를 적용한다. 공통 푸터와 독립된 `floating-contact.js`와 `floating-contact.css`에서 관리한다. 모바일 메뉴가 열리면 버튼을 숨기고, 키보드 포커스와 화면 낭독기용 이름을 제공하며, 마우스오버 툴팁은 표시하지 않는다.
- 공통 헤더: 실제 마크업은 `header.html`이 소유하고 `header-fallback.js`는 그와 완전히 동일한 `file://` 직접 미리보기용 본본을 제공한다. 각 페이지는 `#site-header-root`만 선언하고 `header.js`가 HTTP에서는 `header.html`, 파일 미리보기에서는 폴백을 불러온 뒤 현재 메뉴의 `aria-current`만 설정한다. 모든 페이지는 같은 모션 로고를 데스크톱 56px, 모바일 28px로 표시하고 4.4초 부근에서 정지한다. 기본 로고 필터는 명도 임계값으로 진한 부분과 연한 부분을 분리한 뒤 검정색 100%·10%로 표시한다. 원본 회색 성분이 진한 마스크에 섞이거나 가장자리 알파가 중복 적용되지 않도록 한다.
- Process: 프로젝트 페이지와 동일한 `.sub-container`, `.sub-wrap`, `.sub-title`, `.btit`, `.stit` 상단 체계를 사용한다. 이후 세 구간 헤더와 아홉 개의 일러스트 카드로 구성하며, 4열 데스크톱·2열 태블릿(769–1180px)·1열 모바일(최대 768px)을 유지하고 `prefers-reduced-motion`에서는 스크롤 리빌을 정적으로 표시한다.
- Process는 전체 단계를 빠르게 훑도록 상단 패딩 PC 140px·모바일 96px, 제목 블록 아래와 제목·설명 사이는 공통 제목 여백 변수를 따른다. 제목·소개 글자 크기는 프로젝트 페이지와 동일하게 PC 제목 `clamp(40px, 5vw, 96px)`·소개 19px이며, 모바일은 제목 40px·소개 19px다. 소개 행간은 메인과 동일한 1.5로 맞춘다.
- Process의 구간 제목(`.process-phase-title h2`)은 크기 32px·굵기 500으로 표시하고 기존 9ch 너비 제한을 해제해 모든 제목을 한 줄로 표시한다. 데스크톱(≥1181px)에서는 왼쪽 구간 제목과 오른쪽 단계 제목의 상단을 동일한 높이로 맞춘다. 왼쪽도 숫자 26px·이미지와 상하 간격 228px에 대응하는 행을 사용하며 태블릿·모바일의 세로 구간 안내는 유지한다.
- Process 일러스트는 사용자 제공 `프로세스_02기준_라인통일`의 1024×1024 투명 PNG 9장을 `assets/process/unified/`에서 번호별로 사용한다. 통일본은 기존 192px 이미지 영역 안에 전체 캔버스가 들어가도록 표시한다. 05번은 사무실 평면·체크 표시, 06번은 회의 공간·체크 표시를 사용하며, 08번은 의자 카탈로그·마감재 샘플, 09번은 완성된 사무 공간을 표시한다.
- Process 카드는 기존 숫자 → 중앙 일러스트 → 하단 설명의 세로 배치를 유지한다. 순서 숫자 26px, 단계 제목과 본문 크기를 유지한다. 일러스트 너비는 기존 대비 약 90%(최대 PC 270px·모바일 252px)이며, 정사각 PNG의 빈 상하 여백은 높이 192px의 표시 영역에서 숨긴다. 숫자와 이미지 사이 12px, 이미지와 설명 사이 24px를 두고, 카드 패딩은 PC 24–36px(하단 32–48px)·모바일 상단 28px/하단 32px로 균형을 맞춘다. 이미지 영역은 남는 높이를 채우지 않으며 카드 높이는 콘텐츠에 맞춰 자연스럽게 정해진다.
- About Alternative: 기존 수치인 업계 경력 14년·프로젝트 누적 250+와 One-stop Service 8개 항목만 사용한다. 데스크톱은 상단 1개와 하단 2개의 지표 구조, 모바일은 단일 열로 전환하며 프로젝트 이미지는 가로 스크롤과 스냅으로 탐색한다.
- 히어로: 고객 전달 배너 사진 5개를 스튜디오비사이드 → 노보네시스 → 카카오 → 에이펫 → 메디스팬 순으로 노출한다. 기존 영상 2개와 이전 배너 사진은 히어로에서 제거한다. 사진만 7초 간격으로 전환하고, `We Design Together` / `일하고싶은공간, 디자인코드가함께설계합니다.` 문구는 슬라이드 바깥의 단일 고정 레이어로 유지한다. 진행 막대는 5개이며 이전·다음 버튼과 좌우 키 탐색을 제공한다.
- 프로젝트: 원본 WORK 카드의 정사각형·타이포·메타·선 재사용. 3열은 사용자 지정.
- 메인 Featured Work 카드는 최초 원본의 90%를 정수 px로 반올림해 표시한다. 프로젝트명은 15–20px이며 원본의 반응형 비율을 유지한다. 업종·평수는 메인과 프로젝트 목록 모두 CSS에 정수 px를 직접 지정한다. 기본 13px, 1620px 이상 14px, 1740px 이상 15px이며 소수점·vw·round 계산식을 사용하지 않는다. 이미지 위 프로젝트명은 정수 px를 직접 지정하며 1920px에서 20px, 주소는 15px로 두 페이지에서 동일하게 표시한다. CSS `round()` 미지원 브라우저는 정수 크기 폴백을 사용한다.
- Featured Work와 프로젝트 목록 썸네일의 호버·키보드 포커스 추가 정보는 유지하며, 오버레이 오른쪽 하단에 사용자 참고 이미지 형태의 흰색 우상향 화살표(↗)를 함께 표시한다. 화살표 크기는 PC 24px·터치 화면 18px, SVG 선 두께는 1.5로 표시한다. 기존 카드별 클릭 동작을 유지한다. 터치 화면에서는 기존 정보와 화살표를 항상 표시하며 텍스트와 겹치지 않도록 오른쪽 공간을 확보한다.
- 프로젝트 목록 페이지(`work.html`)의 카드 프로젝트명은 메인과 동일한 원본 대비 90% 크기를 적용한다. 호버 텍스트·우상향 화살표 크기는 메인과 동일하게 표시한다. 업종·평수는 메인과 동일한 정수 px 규칙을 따른다.
- 프로젝트 목록은 데스크톱·태블릿 3열, 모바일(≤768px) 2열로 표시한다. 제목·필터 사이에 여유를 주면서 첫 화면에 사진이 보이도록 상단 패딩은 PC 140px·모바일 96px, 제목 블록 아래와 제목·설명 사이는 공통 제목 여백 변수를 따르며 필터 아래 여백은 36px·28px로 표시한다.
- 프로젝트 페이지 제목 영역은 축소한 전용 타이포를 사용한다. PC 제목은 `clamp(40px, 5vw, 96px)`, 소개 문구는 19px, 필터는 `clamp(14px, .938vw, 18px)`이며 모바일(≤768px)은 제목 40px·소개 19px로 표시한다.
- 히스토리: 원본 `.award-block > .award-year + .award-list > .award-item` 구조와 반응형을 유지. 구분 제목에는 `2026`, `2025`, `2024` 연도만 표시하고 각 블록에 프로젝트명과 영문명을 표시하며 원본 수상 배지는 사용하지 않음. 연도별 구분선은 유지.
- Difference: 카드 내부 영문 상세 타이틀은 사용하지 않고 한글 제목과 설명만 표시한다. 3D 제안·A/S·면허·촬영은 각각 공간 프레임·연결 궤도·건축 그리드 인증·뷰파인더로 표현한다.
- 차별화: 원본 `.blob` 도형과 원본 베이지 표면에 5가지 기준 배치.
- 파트너: 4열 × 2줄 로고 슬롯. 로고 이미지는 슬롯의 가로·세로 80% 크기로 중앙 배치하며 두 로고 행 사이 간격은 0으로 연결한다. 실제 파트너 로고 미수령.
- FAQ: 원본 질문 행과 아이콘을 사용하되 클릭·키보드 아코디언으로 확장. 자동 이동 track/mask는 제거해 답변을 읽을 수 있게 한다.
- 공통 푸터: 실제 마크업은 `footer.html`, 스타일은 `footer.css`에서 관리하며 `footer-fallback.js`는 동일한 `file://` 직접 미리보기용 본본을 제공한다. 메인·프로젝트 목록·프로세스·상담신청은 `footer.js`로 공통 푸터를 불러오고, 프로젝트 상세는 푸터 리소스를 로드하지 않는다. 푸터가 뷰포트에 진입하면 주황색 배경이 올라오고 `Contact Us` 문자, 안내 문구, 문의 버튼, 하단 정보가 순차적으로 등장한다. 일반 페이지는 메인과 동일한 sticky reveal, `70svh` 최소 높이, 곡선 전환을 사용한다. 회사정보 영역의 브랜드 마크는 사용자 제공 고정형 `assets/brand/footer-logo.png`를 원본 색상 그대로 사용한다. 시스템의 모션 감소 설정이 켜져 있으면 전환 없이 즉시 표시한다.

## Accessibility
- 슬라이더 이전·다음·정지, 키보드 좌우 키, 모바일 메뉴 Escape 지원.
- FAQ는 실제 button과 aria-expanded/controls, hidden 답변.
- reduced-motion에서는 자동 슬라이드 진행을 정지하고 장식 모션을 없앤다.
- WCAG 전면 인증을 주장하지 않는다.

## Responsive behavior
- 메인·프로젝트 목록 모두 >768px 3열, ≤768px 2열.
- 모바일 차별화 2열, 파트너 2열, FAQ 세로, 푸터 세로.
- 메뉴는 ≤768px 전체 화면. 본문 anchor scroll margin은 고정 헤더를 고려한다.

## Interaction states
- 공통 테두리 버튼(`.more-btn`): 프로젝트 CTA는 `전체 프로젝트 보기`, 메인 FAQ(Questions? Answered.) 영역 CTA는 `상담신청하기`, 상담 폼 하단 버튼은 `상담신청`으로 표시한다. 글자 크기는 PC `28px`, 모바일(768px 이하) `24px`로 표시한다. 모바일은 직전 PC·모바일 크기 비율(26:22)에 맞춰 반올림한다. 기존 모양·여백·화살표 동작을 유지하며 hover와 키보드 포커스에서는 글자·테두리·화살표를 브랜드 오렌지(`--primary`)로 바꾼다.
- 슬라이더 7초 자동 전환. 화면이 숨겨지거나 히어로를 벗어나거나 모션 감소 설정이 켜지면 자동 진행을 정지한다.
- 노보네시스 카드는 실제 상세 페이지로 연결하고, 상세가 없는 다른 카드에는 가짜 링크를 만들지 않는다. 전체 프로젝트 링크는 실제 WORK 페이지로 연결.
- 상담은 전용 페이지로 이동한다. 상담 폼은 데이터 연결, 제출, 메일 앱 호출 없이 화면 구성만 제공하는 정적 마크업이다.
- 파트너는 로딩 상태가 아닌 자료 미수령 플레이스홀더. 히스토리는 제공된 자료를 반영.

## Content voice
- 카피는 기업 공간 설계 관점의 제안 문구. 푸터 영문 메시지는 공간과 일하는 방식의 연결을 강조하는 `Let’s design the way you work.`를 사용한다. 차별화·FAQ는 고객 검수 전 초안.
- 연혁·파트너·기간·보장 사항을 사실처럼 채우지 않는다.
- 데이터는 `home-content.js`, 프로젝트는 `projects.js`. 원본 스크립트나 외부 추적 코드 없음.
